# 라즈베리파이 추론 엔진 선정 보고서

- 작성일: 2026-10-15
- 대상 모델: `yolo26n` (Ultralytics 8.4.175, 입력 640×640, FP32)
- 비교 엔진: ONNX Runtime, NCNN, OpenVINO, LiteRT(TFLite)

## 1. 요약

**라즈베리파이 배포 엔진으로 NCNN을 권장한다.** 최종 확정은 실기기 측정 후에 한다.

- **정확도:** 네 엔진 모두 PyTorch 원본과 mAP가 같다(mAP50 0.6428, mAP50-95 0.4772). 따라서 엔진은 속도, 안정성, 배포 편의성만 보고 고르면 된다.
- **용량:** 네 엔진 모두 9.8~10.1 MB로 차이가 거의 없다.
- **속도(x86 측정):** LiteRT(p50 53.8 ms)와 ONNX Runtime(56.5 ms)이 가장 빨랐다. NCNN(82.3 ms)이 가장 느렸다.
- **속도(라즈베리파이 5 공식 벤치마크):** 순위가 정반대다. NCNN이 67 ms로 가장 빠르고, OpenVINO 105 ms, LiteRT 123 ms, ONNX 126 ms 순이다. NCNN은 ARM CPU에 맞춰 최적화된 엔진이라, 실제 배포 환경에서는 x86 측정 결과보다 공식 벤치마크를 따른다.
- **차선책:** OpenVINO, LiteRT, ONNX Runtime은 105~126 ms로 비슷한 2군이다. 이 셋 중에서는 실기기 측정 결과로 고른다.

## 2. 배경과 목적

`yolo26n` 객체 탐지 모델을 라즈베리파이(ARM64 CPU)에 배포하려고 한다. 이를 위해 같은 모델을 4개 추론 엔진으로 변환하고 정확도, 속도, 용량을 비교했다. 실기기가 없어서 Docker 컨테이너로 x86 환경과 ARM64 에뮬레이션 환경을 만들어 측정했다.

## 3. 테스트 환경

두 컨테이너는 같은 Dockerfile로 만들었다. 라즈베리파이 4/5의 자원에 맞춰 둘 다 CPU 4개, 메모리 4 GB로 제한했다.

| 항목 | x86 컨테이너 | ARM64 컨테이너 (라즈베리파이 대체) |
|---|---|---|
| CPU 아키텍처 | x86_64 (Intel Core Ultra 5 125H, 네이티브 실행) | aarch64 (QEMU 에뮬레이션) |
| OS / Python | Debian 13 (trixie), Python 3.13 | Debian 13 (trixie), Python 3.13 |
| 용도 | TFLite 변환, 엔진 간 속도 비교 | 배포 환경 동작 및 정확도 확인 |
| 속도 수치의 의미 | 엔진 간 상대 비교에 사용 가능 | 실제 라즈베리파이 속도와 무관 |

두 컨테이너에 공통으로 쓴 소프트웨어 버전은 다음과 같다.

| 구분 | 소프트웨어 | 버전 |
|---|---|---|
| 프레임워크 | ultralytics | 8.4.175 |
| 프레임워크 | torch (CPU) | 2.14.1 |
| 엔진 | onnxruntime | 1.31.0 |
| 엔진 | openvino | 2026.4.1 |
| 엔진 | NCNN | 1.0.20260526 |
| 변환 도구 | PNNX (NCNN 변환) | 20260526 |
| 변환 도구 | litert_torch (TFLite 변환) | 0.9.4 |

## 4. 측정 방법

| 항목 | 방법 |
|---|---|
| 데이터 | COCO128 (이미지 128장, 정답 박스 929개) |
| 정확도 | Ultralytics `val`. 모든 엔진에 같은 조건 적용(640×640 정사각형 레터박스, `batch=1`) |
| 속도 | 각 엔진의 자체 API를 직접 호출. 스레드 4개, 미리 전처리한 같은 입력 텐서 사용. 워밍업 100회 후 128장을 측정. 추론 시간만 재고 전처리·NMS는 제외 |
| 용량 | 엔진이 실제로 불러오는 모델 파일의 합계 (`.onnx`, `.param`+`.bin`, `.xml`+`.bin`, `.tflite`) |
| 출력 검증 | 첫 이미지의 출력 텐서를 PyTorch 출력과 비교 (최대 절대 오차) |

- 모든 엔진은 같은 설정(FP32, 640×640 고정 입력, `nms=None`)으로 내보냈다.
- PyTorch 기준 모델도 내보낸 그래프와 같은 구조로 맞췄다(fuse, end2end 끔).
- 사용한 스크립트는 `export_engines.py`(변환)와 `compare_engines.py`(비교)이다.

## 5. 결과 1: 정확도와 모델 용량

| 엔진 | 용량 (MB) | mAP50 | mAP50-95 | 출력 최대 오차 (픽셀, PyTorch 대비) |
|---|---|---|---|---|
| PyTorch (기준) | 5.54 | 0.6428 | 0.4772 | 0 |
| ONNX Runtime | 9.93 | 0.6428 | 0.4772 | 3.11e-03 |
| NCNN | 9.76 | 0.6428 | 0.4772 | 3.63e-03 |
| OpenVINO | 10.09 | 0.6428 | 0.4772 | 2.56e-03 |
| LiteRT (TFLite) | 9.97 | 0.6428 | 0.4772 | 3.65e-03 |

- **정확도:** 네 엔진 모두 변환으로 인한 정확도 손실이 없다. 출력 오차는 0.004픽셀 이하로, float32 계산 방식 차이에서 생기는 수준이다.
- **용량:** `.pt`가 절반 크기인 이유는 가중치를 FP16으로 저장하기 때문이다. 변환한 모델은 모두 FP32다.
- **용량 줄이기:** 용량이나 속도를 더 줄이려면 FP16이나 INT8 양자화를 검토할 수 있다. 다만 양자화하면 정확도를 다시 검증해야 한다.

## 6. 결과 2: 추론 속도 (x86 기준)

x86 컨테이너에서 128장을 측정했다(워밍업 100회, 스레드 4개, 단위 ms).

| 엔진 | p50 | p90 | p95 | p99 | 최대 | 평균 | FPS (p50) |
|---|---|---|---|---|---|---|---|
| LiteRT (TFLite) | **53.8** | 60.3 | **64.5** | 73.0 | **76.2** | 54.0 | **18.6** |
| ONNX Runtime | 56.5 | 61.8 | 64.6 | 74.5 | 148.4 | 57.7 | 17.7 |
| OpenVINO | 68.2 | 73.6 | 77.4 | 81.4 | 94.6 | 68.8 | 14.7 |
| NCNN | 82.3 | 93.1 | 96.7 | 105.9 | 141.0 | 83.9 | 12.2 |
| PyTorch (기준) | 118.4 | 128.1 | 131.3 | 144.4 | 167.1 | 119.5 | 8.4 |

- **LiteRT와 ONNX Runtime:** p50 차이는 2.7 ms(약 5%)다. 이 PC에서 반복 측정할 때 생기는 편차보다 작아서, 두 엔진은 사실상 동률이다. 다만 최대값은 LiteRT(76 ms)가 ONNX Runtime(148 ms)보다 훨씬 안정적이었다.
- **OpenVINO:** Intel CPU에서 실행했는데도 3위였다.
- **NCNN:** x86에서는 가장 느렸다. NCNN은 ARM용 최적화가 중심인 엔진이다.
- **해석할 때 주의할 점:** 이 순위는 x86 CPU에서의 결과다. 엔진마다 최적화한 CPU가 달라서 라즈베리파이에서는 순위가 바뀔 수 있다.

## 7. 결과 3: ARM64(라즈베리파이 대체) 환경 동작 확인

> 측정 진행 중. 완료되면 이 절에 결과를 추가한다.

이미 확인된 사항은 다음과 같다.

- **Parity check:** ARM64 컨테이너에서 `.pt`와 `.onnx` 결과를 비교했고 통과했다. 출력 최대 오차는 0.0058픽셀, 탐지 결과(클래스, 박스, 신뢰도)는 같았다.
- **엔진 설치:** 네 엔진 모두 ARM64(aarch64)용 패키지로 설치됐다.

## 8. 참고: 라즈베리파이 5 공식 벤치마크

Ultralytics가 라즈베리파이 5에서 같은 `yolo26n` 모델(FP32, 입력 640)을 측정한 결과다. 추론 시간에는 전처리와 후처리가 포함되지 않는다. 이번 비교 대상인 네 엔진만 옮겼다. ([출처](https://docs.ultralytics.com/guides/raspberry-pi/))

| 엔진 | 용량 (MB) | mAP50-95 | 추론 시간 (ms/장) | 우리 x86 측정 p50 (ms) |
|---|---|---|---|---|
| **NCNN** | 9.4 | 0.4784 | **67.03** | 82.3 (4위) |
| OpenVINO | 9.6 | 0.4734 | 104.55 | 68.2 (3위) |
| LiteRT | 9.8 | 0.4730 | 123.30 | 53.8 (1위) |
| ONNX | 9.5 | 0.4734 | 125.99 | 56.5 (2위) |
| PyTorch (참고) | 5.3 | 0.4760 | 299.09 | 118.4 |

- **순위가 뒤집혔다.** x86에서 가장 느렸던 NCNN이 라즈베리파이 5에서는 가장 빠르다. 2위인 OpenVINO보다도 약 36% 빠르다. x86 결과로 라즈베리파이용 엔진을 고르면 안 된다는 근거다.
- **공식 가이드도 NCNN을 권장한다.** 가이드는 NCNN이 라즈베리파이에서 가장 좋은 추론 성능을 낸다고 밝히고, 이유로 ARM 같은 모바일·임베디드 플랫폼에 고도로 최적화돼 있다는 점을 든다.
- **mAP 차이는 측정 환경 차이다.** 공식 표의 엔진 간 mAP 차이(0.4730~0.4784)는 측정 조건이 달라서 생긴 것으로 보인다. 같은 조건으로 잰 이번 측정에서는 네 엔진의 mAP가 같았다.

## 9. 엔진별 라즈베리파이 적합성 분석

| 엔진 | 라즈베리파이 적합성 | 근거 | 주의할 점 |
|---|---|---|---|
| **NCNN** | 높음 (1순위) | ARM NEON 최적화가 중심인 엔진이다. 라즈베리파이 5에서 67 ms로 가장 빠르다. 의존성이 가볍다 | x86에서는 가장 느렸다. 개발 PC에서의 속도로 판단하면 안 된다 |
| **OpenVINO** | 중간 | 라즈베리파이 5에서 105 ms로 2위다. ARM CPU 플러그인이 있다 | Intel 하드웨어 중심의 엔진이다. 패키지가 무겁다 |
| **LiteRT (TFLite)** | 중간 | 라즈베리파이 5에서 123 ms다. 런타임(`ai-edge-litert`)이 가볍다. x86에서는 가장 빠르고 최대값도 가장 안정적이었다 | 변환은 Linux x86이나 macOS에서만 된다. 변환 도구 설치에 약 14분이 걸렸다 |
| **ONNX Runtime** | 중간 | 라즈베리파이 5에서 126 ms다. 지금 코드(`test_onnx.py`, `benchmark_onnx.py`)를 그대로 쓸 수 있다 | 기본 설정에서는 스레드를 과하게 만든다. `intra_op_num_threads=4`를 꼭 지정해야 한다 |

## 10. 권고안과 다음 단계

**권고:** NCNN을 배포 엔진으로 정하고, 실기기에서 성능을 확인한다. ONNX Runtime은 기존 코드를 그대로 쓸 수 있으니 비교 기준(baseline)으로 함께 잰다.

실기기 검증 계획은 다음과 같다.

1. 라즈베리파이 64비트 OS에 `requirements.txt`의 패키지를 설치한다.
2. 변환된 모델 파일을 복사한다. 대상은 `yolo26n.onnx`, `yolo26n_ncnn_model/`, `yolo26n_openvino_model/`, `yolo26n.tflite`다.
3. `python compare_engines.py --threads 4`를 실행해 실제 속도를 측정한다.
4. 발열로 인한 속도 저하(스로틀링)를 확인한다. 5분 이상 연속으로 추론하면서 p95와 최대값이 어떻게 변하는지 본다.
5. 목표 속도에 못 미치면 다음을 검토한다.
    - 입력 크기를 줄인다(640 → 480 또는 320).
    - FP16 또는 INT8 양자화를 적용한다(정확도 재검증 필요).

## 11. 한계와 유의사항

- **ARM64 결과로는 속도를 판단할 수 없다.** ARM64 컨테이너는 QEMU 에뮬레이션으로 돌아가므로 속도 수치가 실제 라즈베리파이 성능을 나타내지 않는다. 특히 엔진별 ARM 최적화(NEON, XNNPACK)가 실제처럼 반영되지 않는다.
- **x86 속도도 한 번만 측정한 결과다.** 노트북의 전원 모드와 발열에 따라 측정마다 p95가 크게 달라졌다(같은 설정에서 59~99 ms). 순위를 확정하려면 반복 측정이 필요하다.
- **mAP가 실제보다 높게 나왔을 수 있다.** COCO128은 COCO 학습 이미지에서 뽑은 데이터라, 모델이 학습 때 본 사진일 수 있다. 엔진 간 상대 비교에는 문제없지만, 모델 성능 자체를 판단하려면 학습에 쓰지 않은 데이터로 평가해야 한다.
- **측정한 시간은 엔진 추론만 포함한다.** 전처리(약 7 ms)와 NMS 후처리(약 3 ms, x86 기준)는 엔진과 관계없는 공통 비용이라 제외했다.
- **공식 벤치마크는 라즈베리파이 5 기준이다.** 라즈베리파이 4에서는 절대 속도가 더 느리다. 순위도 실기기에서 다시 확인해야 한다.
