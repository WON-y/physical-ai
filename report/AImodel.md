# 비전 AI 모델 학습 보고서

> 작성일: 2026-10-12
> 학습 모델: YOLOE, DINO-X, SAM3, SigLIP2, OCR, MediaPipe

## 1. YOLOE (Real-Time Seeing Anything)

**개요**
YOLO 계열의 실시간 성능을 유지하면서, 미리 학습한 클래스에 한정되지 않고 임의의 객체를 찾을 수 있는 **개방형 어휘(Open-Vocabulary) 객체 검출·세그멘테이션 모델**이다.

**주요 기능 (3가지 프롬프트 방식)**

| 방식          | 설명                                            | 예시                                                    |
| ------------- | ----------------------------------------------- | ------------------------------------------------------- |
| Text Prompt   | 찾고 싶은 객체를 텍스트로 입력                  | "helmet", "forklift" 입력 → 해당 객체 검출             |
| Visual Prompt | 예시 이미지/박스를 주면 비슷한 객체 검출        | 불량 부품 1개를 박스로 지정 → 같은 유형 불량 모두 검출 |
| Prompt-Free   | 프롬프트 없이 이미지 내 모든 객체를 스스로 인식 | 장면 속 사물 전체 자동 태깅                             |

- 박스 검출뿐 아니라 **인스턴스 세그멘테이션**도 지원
- 가볍고 빨라 **실시간 영상·엣지 디바이스**에 적합

**사용 예시**

- 공사 현장 CCTV에서 안전모 미착용자 실시간 탐지
- 매장 진열대 상품 인식, 제조 라인 불량 검출

## 2. DINO-X

**개요**
IDEA Research에서 개발한 **개방형 객체 인식(Open-World Detection) 모델**이다. YOLOE처럼 텍스트·시각·프롬프트 없는 방식을 모두 지원하지만, 대규모 데이터로 학습되어 **정확도가 더 높은 대신 무겁고 느리다**. 보통 클라우드 API로 호출해서 사용한다.

**주요 기능**

- 텍스트·시각·프롬프트 없는 방식의 객체 검출
- 세그멘테이션, 키포인트(자세) 검출, 영역 캡셔닝 등 다양한 인식 작업 지원
- 희귀하거나 긴 꼬리(long-tail) 범주의 객체 인식에 강함

**사용 예시**

- **데이터 라벨링 자동화**: DINO-X로 정확한 라벨을 생성 → 이를 학습 데이터로 YOLO 같은 경량 모델을 학습
- 실시간성이 덜 중요한 고정밀 분석(이미지 검수, 데이터셋 구축)

**YOLOE와 비교**

| 항목   | YOLOE               | DINO-X              |
| ------ | ------------------- | ------------------- |
| 속도   | 빠름 (실시간)       | 느림                |
| 정확도 | 보통~높음           | 매우 높음           |
| 용도   | 실서비스·엣지 배포 | 라벨링·고정밀 분석 |

## 3. SAM3 (Segment Anything Model 3)

**개요**
Meta에서 공개한 **세그멘테이션 특화 모델**로, 객체의 영역을 **픽셀 단위 마스크**로 정밀하게 분할한다. 이전 버전(SAM1·2)은 점·박스로 객체를 하나씩 지정해야 했지만, SAM3는 **텍스트(개념) 프롬프트**로 해당 개념의 모든 객체를 한 번에 찾아 분할한다.

**주요 기능**

- 점·박스·마스크 프롬프트로 특정 객체 분할
- 텍스트·예시 이미지 프롬프트로 **같은 개념의 모든 인스턴스** 분할 (Promptable Concept Segmentation)
- **영상에서의 객체 분할 및 추적(tracking)**

**사용 예시**

- 이미지 배경 제거, 누끼 따기, 사진 편집
- 의료 영상에서 병변 영역 분할
- 세그멘테이션 학습 데이터 라벨링 자동화
- 영상 속 특정 사람·물체 추적

## 4. SigLIP2

**개요**
Google에서 개발한 **비전-언어 인코더 모델**이다. 이미지와 텍스트를 **같은 임베딩 공간의 벡터**로 변환하므로, 두 벡터의 유사도를 계산해 이미지와 텍스트를 직접 비교할 수 있다. (CLIP을 개선한 SigLIP의 후속 모델로, 다국어를 지원한다.)

**주요 기능**

- 이미지 ↔ 텍스트 유사도 계산
- **제로샷(Zero-shot) 분류**: 추가 학습 없이 라벨 텍스트만으로 이미지 분류
- 이미지 ↔ 이미지, 텍스트 ↔ 이미지 검색

**사용 예시**

- "빨간 원피스" 입력 → 쇼핑몰 상품 이미지 검색
- 사진 앨범 자동 분류, 유사 이미지 찾기
- 멀티모달 LLM(VLM)의 이미지 인코더로 활용

## 5. OCR (Optical Character Recognition)

**개요**이미지 속 **텍스트를 찾아서 읽어 디지털 문자로 변환**하는 기술이다. 특정 모델 하나가 아니라 기술 분야를 가리키며, 일반적으로 다음 두 단계로 동작한다.

1. **Text Detection**: 이미지에서 글자가 있는 위치(영역) 검출
2. **Text Recognition**: 검출된 영역의 글자를 인식해 텍스트로 변환

대표 도구로 Tesseract, EasyOCR, PaddleOCR, 네이버 CLOVA OCR 등이 있다.

**사용 예시**

- **네이버 영수증 리뷰**: 영수증을 촬영하면 상호명·날짜·금액을 인식해 방문 인증
- **주민등록증 인식**: 은행·핀테크 앱의 비대면 신원 확인 시 이름·주민번호 자동 입력
- 명함 인식, 문서 디지털화, 자동차 번호판 인식

## 6. MediaPipe

**개요**
Google에서 개발한 **실시간 인체 인식 프레임워크**다. 사람의 신체 **랜드마크(관절·특징점) 좌표**를 추출해 자세와 움직임을 분석할 수 있다. 가벼워서 모바일·웹 환경에서도 실시간으로 동작한다.

**주요 기능**

- **Pose**: 전신 관절 33개 랜드마크 검출
- **Hands**: 손가락 관절 21개 랜드마크 검출
- **Face Mesh**: 얼굴 468개 특징점 검출
- 랜드마크 좌표로 관절 각도·움직임 계산 가능

**사용 예시**

- 홈트레이닝 앱: 스쿼트 자세 교정, 운동 횟수 자동 카운트
- 손동작(제스처) 인식으로 기기 제어
- 낙상 감지, 재활 운동 분석
- 얼굴 필터·AR 효과

## 8. 개인 프로젝트 적용: PPE 착용 점검 로봇

### 8.1 프로젝트 개요

공사 현장을 순찰하는 로봇이 작업자의 **안전모·안전조끼 착용 여부**를 실시간으로 점검하는 프로젝트다. 메인 검출 모델은 COCO 사전학습 **YOLO26**을 person·helmet·vest·head 4개 클래스로 파인튜닝해서 쓰고, Jetson Orin NX에서 15 FPS 이상으로 동작하는 것을 목표로 한다.

### 8.2 YOLO를 다른 모델로 대체하지 않은 이유

| 모델    | 대체하지 않은 이유                                                                                                                         |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| YOLOE   | 강점은 학습하지 않은 객체를 찾는 것인데, 이 프로젝트는 클래스가 4개로 고정되어 있음. 전용으로 파인튜닝한 YOLO26이 정확도·속도 모두 유리함 |
| DINO-X  | 무겁고 클라우드 API 방식이라 로봇에 탑재할 수 없음                                                                                         |
| SAM3    | 픽셀 단위 분할이 필요 없는 박스 기반 판정 구조이고, 연산량이 큼                                                                            |
| SigLIP2 | 위치(박스)를 출력하지 않아 검출 모델로 쓸 수 없음                                                                                          |
| OCR     | 프로젝트 목적과 관련 없음                                                                                                                  |

→ **실시간 검출은 YOLO26이 맡고**, 학습한 모델 중 **DINO-X와 MediaPipe를 보조 모델로 추가**한다.

### 8.3 보조 모델 1: DINO-X를 이용한 자동 라벨링

**적용 위치**: 학습 데이터 준비 단계 (오프라인, 로봇에는 탑재하지 않음)

**목적**
자체 현장 데이터(2,000장 이상)와 AIHub 데이터는 라벨이 없거나 우리 클래스 정의와 맞지 않는다. 사람이 처음부터 박스를 그리면 시간이 많이 걸리므로, 정확도가 높은 DINO-X로 **초벌 라벨을 자동 생성**하고 사람은 검수만 한다.

**방법**

1. 텍스트 프롬프트로 4개 클래스를 검출한다.
   - person → "person"
   - helmet → "hard hat", "safety helmet"
   - vest → "safety vest", "reflective vest"
   - head → "head"
2. 신뢰도(confidence) 0.3 이상인 박스만 남긴다.
3. **후처리**: head 박스가 helmet 박스와 많이 겹치면 안전모를 쓴 머리이므로 head 라벨을 삭제한다. (이 프로젝트에서 head는 '안전모를 쓰지 않은 머리'로 정의했기 때문)
4. 결과를 YOLO 형식(txt)으로 변환한다.
5. 사람이 검수하며 틀린 박스를 수정한다. **test셋은 반드시 전수 검수**한다.

**기대 효과**

- 라벨링 시간 단축 (박스를 새로 그리는 대신 수정만 함)
- 기존 계획(COCO 모델로 person만 자동 라벨링)보다 넓게 보호구 클래스까지 자동화
- "**큰 모델로 라벨링 → 작은 모델로 배포**"하는 실무 방식 적용

**검증 방법**
사람이 직접 라벨링한 이미지 100장에서 DINO-X 라벨과 비교해 클래스별 Precision·Recall을 확인하고, 신뢰도 임계값을 조정한다.

### 8.4 보조 모델 2: MediaPipe Pose를 이용한 착용 판정 보강

**적용 위치**: 착용 판정 단계 (로봇에서 YOLO 검출 이후 실행)

**목적**
기존 판정 규칙은 사람 박스를 **고정 비율**로 나눈다. (상단 25% = 머리, 높이 20~65% = 상체)
하지만 허리를 숙이거나, 앉아 있거나, 몸 일부가 가려지면 실제 머리·상체 위치와 비율이 어긋나 **오판정**이 생긴다. MediaPipe Pose로 실제 관절 위치를 찾아 판정 영역을 사람의 자세에 맞춘다.

**방법**

1. YOLO26이 검출한 person 박스로 이미지를 잘라 MediaPipe Pose에 입력한다.
2. 33개 랜드마크 중 필요한 점만 사용한다.

| 판정 영역 | 사용 랜드마크                    | 영역 설정                                    |
| --------- | -------------------------------- | -------------------------------------------- |
| 머리      | 코(0), 양 귀(7, 8)               | 귀 사이 너비를 기준으로 위쪽까지 확장한 박스 |
| 상체      | 양 어깨(11, 12), 양 골반(23, 24) | 어깨~골반을 감싸는 박스                      |

3. 이 영역 안에 helmet·vest 박스가 들어간 비율(포함률)로 착용 여부를 판단한다.
4. 랜드마크 visibility가 낮으면(가려짐) **기존 고정 비율 규칙으로 대체**한다.

**속도 고려**
사람 수만큼 추론이 늘어나므로, 고정 비율 규칙으로 판정이 애매한 경우(포함률이 임계값 근처)에만 MediaPipe를 실행한다. Jetson에서 전체 15 FPS가 유지되는지 확인한다.

**검증 방법**
같은 판정 테스트셋(사람 500명 이상, 미착용 30% 이상)으로 두 방식을 비교한다.

| 판정 방식             | 미착용 Recall | 미착용 Precision | FPS |
| --------------------- | ------------- | ---------------- | --- |
| 고정 비율 규칙 (기존) |               |                  |     |
| MediaPipe Pose 보강   |               |                  |     |

목표: 미착용 Recall ≥ 0.95, Precision ≥ 0.90, 15 FPS 이상

### 8.5 최종 파이프라인

| 단계           | 모델                                   | 실행 위치     | 역할                                      |
| -------------- | -------------------------------------- | ------------- | ----------------------------------------- |
| ① 데이터 준비 | **DINO-X**                       | PC / 클라우드 | 보호구·사람 자동 라벨링 → 사람이 검수   |
| ② 모델 학습   | YOLO26 (n·s·m 비교)                  | PC (GPU)      | 4클래스 파인튜닝                          |
| ③ 실시간 검출 | YOLO26 (TensorRT FP16)                 | Jetson 로봇   | person·helmet·vest·head 검출           |
| ④ 착용 판정   | **MediaPipe Pose** + 포함률 규칙 | Jetson 로봇   | 자세에 맞춘 머리·상체 영역으로 착용 판단 |
| ⑤ 이벤트 확정 | 규칙                                   | Jetson 로봇   | 연속 5프레임 미착용 시 알림               |

### 8.6 정리

- 수업에서 배운 6개 모델 중 **실시간 검출에는 파인튜닝한 YOLO가 가장 적합**하다는 결론을 내렸다.
- **DINO-X**는 정확하지만 무거운 특성을 살려 **로봇이 아닌 데이터 준비 단계**에 활용했다.
- **MediaPipe**의 관절 분석 기능을 활용해, 박스만으로는 놓치던 **사람의 자세**를 착용 판정에 반영했다.
- 각 모델의 장단점(속도·정확도·실행 환경)을 고려해 **역할을 나누는 것**이 하나의 모델로 모든 일을 처리하는 것보다 효과적이라는 점을 배웠다.
