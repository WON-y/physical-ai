## 하드웨어 구성도 (Raspberry Pi 5 기준)

> 예시 모델과 수치는 대표 부품 기준이다. 실제 부품을 정한 뒤 데이터시트로 다시 확인한다.
> 경광등·스피커 등 핵심 기능에 꼭 필요하지 않은 부품은 제외했다.
> 피크 전류: 부품이 켜지거나 모터가 출발·회전할 때 순간적으로 흐르는 최대 전류. 전원·퓨즈·전선은 평균이 아닌 **피크 전류 기준**으로 고른다.

### 1. 전체 관계도

```text
 [ 입력 ]                    [ 처리 ]                         [ 출력 ]

 카메라 모듈 3 ──MIPI CSI-2──┐                         ┌──Wi-Fi──▶ 현장 Wi-Fi 공유기
   (영상 입력)               │                         │              │ 인터넷 (MQTT/TLS)
                             ▼                         │              ▼
 2D LiDAR ──────USB─────▶ Raspberry Pi 5 ──────────────┘          알림 서버
   (주변 거리 측정)        + AI HAT+ (PCIe)                           │ 카카오 알림톡 / SMS / 웹 푸시
                             │       ▲                                ▼
                             │       │ GPIO (상태 감지)           관리자 스마트폰
                   USB       │       │
             (Packet Serial) │       └──────────── E-Stop (비상정지 버튼)
                             ▼                         │
                     모터 컨트롤러 ◀──────────────────┘ 모터 전원 직접 차단 (컨택터)
                       (RoboClaw)
                    PWM 전력 │  ▲ 엔코더 신호 (A/B)
                             ▼  │
                     DC 기어드 모터 ×4 (엔코더 내장)
```

**역할 분담**

- **Raspberry Pi 5**: 영상 수신, 주행 경로 계산(ROS 2), 착용 판정, 알림 전송
- **AI HAT+**: YOLO 추론 가속
- **모터 컨트롤러**: 속도 명령대로 모터를 구동하고, 엔코더로 실제 속도를 맞추며(PID), **모터 전류를 제한**

### 2. 기능별 동작 흐름

#### 2.1 카메라 → SBC (영상 입력)

1. 카메라 모듈이 영상을 촬영한다 (1080p, 30 FPS).
2. **MIPI CSI-2** 리본 케이블로 Pi 5에 영상을 전송한다.
3. Pi 5가 프레임을 640×640으로 줄여 **PCIe**로 AI HAT+에 넘긴다.
4. AI HAT+가 YOLO 추론으로 person·helmet·vest·head를 검출하고 결과를 Pi에 돌려준다.
5. Pi가 착용 여부를 판정하고, 연속 5프레임 미착용이면 이벤트로 확정한다.

#### 2.2 SBC → 관리자 (알림 전송)

1. Pi 5가 이벤트(유형, 시각, 위치, 얼굴을 블러 처리한 증빙 사진)를 만든다.
2. 내장 **Wi-Fi**로 현장 공유기에 접속해 **MQTT(TLS 암호화)**로 서버에 전송한다.
3. 서버가 **카카오 알림톡·SMS·웹 푸시**로 관리자에게 알린다.
4. Wi-Fi가 끊기면 microSD에 저장해 두었다가 연결이 복구되면 다시 보낸다.

#### 2.3 로봇 이동

1. 2D LiDAR가 주변 360° 거리를 측정해 **USB**로 Pi에 보낸다.
2. Pi가 ROS 2(위치 추정, Nav2)로 다음 웨이포인트까지 경로를 만든다.
3. Pi가 좌·우 바퀴 속도 명령을 **USB(Packet Serial)**로 모터 컨트롤러에 보낸다.
4. 모터 컨트롤러가 **가속 제한을 적용해** 모터에 PWM 전력을 공급하고, 엔코더 신호로 속도를 보정한다.
5. 모터 컨트롤러가 엔코더 값·모터 전류·배터리 전압을 Pi에 돌려준다.
6. E-Stop을 누르면 **컨택터가 모터 전원을 즉시 차단**하고, Pi는 GPIO로 이를 감지해 기록한다.

### 3. 부품 간 통신 방식

| 연결                    | 물리 연결                       | 통신 방식                          | 주고받는 데이터                   | 방향   |
| ----------------------- | ------------------------------- | ---------------------------------- | --------------------------------- | ------ |
| 카메라 → Pi 5          | 리본 케이블 (22핀)              | MIPI CSI-2                         | 원본 영상 프레임                  | 단방향 |
| Pi 5 ↔ AI HAT+         | FFC 케이블                      | PCIe Gen 3 ×1                     | 입력 이미지 / 검출 결과           | 양방향 |
| LiDAR → Pi 5           | USB 케이블 (USB-UART 변환 내장) | UART 시리얼                        | 360° 거리 데이터                 | 단방향 |
| Pi 5 ↔ 모터 컨트롤러   | USB 케이블                      | Packet Serial (가상 시리얼 포트)   | 속도 명령 / 엔코더 값·전류·전압 | 양방향 |
| 모터 컨트롤러 → 모터   | 전원선                          | PWM 전력 출력                      | 모터 구동 전력                    | 단방향 |
| 엔코더 → 모터 컨트롤러 | 신호선                          | 직교 엔코더 (A/B 펄스)             | 바퀴 회전량·방향                 | 단방향 |
| E-Stop → 컨택터        | 제어선                          | 하드와이어 (컨택터 코일 차단)      | 모터 전원 ON/OFF                  | 단방향 |
| E-Stop → Pi 5          | 신호선                          | GPIO 디지털 입력 (3.3V, 풀업)      | 비상정지 상태                     | 단방향 |
| Pi 5 → 공유기          | 무선                            | Wi-Fi 5 (802.11ac) + MQTT over TLS | 이벤트, 증빙 사진, 로봇 상태      | 양방향 |
| 서버 → 관리자          | 인터넷                          | 카카오 알림톡 / SMS / 웹 푸시      | 미착용 알림, 대시보드 링크        | 단방향 |

> 4륜 스키드 스티어 방식: 왼쪽 모터 2개는 컨트롤러 채널 1, 오른쪽 모터 2개는 채널 2에 연결한다.

### 5. 전원 분배와 보호 회로

```text
배터리 (25.6V)
 └── 메인 퓨즈 60A ── 메인 스위치
      ├── E-Stop 컨택터 (100A) ── 모터 퓨즈 50A ── 모터 컨트롤러 ── 모터 ×4
      └── 전장 퓨즈 3A ── DC-DC (24V → 5.1V, 8A) ── Raspberry Pi 5 (USB-C 입력)
                                                       ├── AI HAT+   (PCIe·GPIO 헤더)
                                                       ├── 카메라     (CSI 커넥터 3.3V)
                                                       └── 2D LiDAR  (USB 5V)
```

#### 5.1 전원 레일별 전류 합계

**5V 레일 (DC-DC 출력)**

| ---------------- | ----------------------- | ----------------------- |
| Raspberry Pi 5   | 1.5A                    | 2.5A                    |
| AI HAT+          | 0.5A                    | 1.0A                    |
| 카메라 (5V 환산) | 0.15A                   | 0.2A                    |

→ DC-DC 변환기는 피크의 약 1.7배인 **8A(40W)**급으로 선정한다.

**24V 레일 (배터리 출력)**

| ------------------------------ | ----------------- | -------------------------------------- |

| 모터 채널 2 (오른쪽 모터 2개)  | 약 2A             | 출발 약 16A / 전류 제한값 25A          |
| DC-DC 입력 (5V 레일, 효율 90%) | 약 0.6A           | 약 1.2A (배터리 전압이 낮을 때)        |

### 6. 피크 전류 대응 설계

| 항목                         | 문제                                                                                                       | 대응                                                                                                  |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **모터 구속 전류**     | 바퀴가 걸리면 모터 2개가 한 채널에서 최대 40A를 끌어, RoboClaw 2×15A의 채널 피크 30A를 넘음               | RoboClaw 설정에서**채널당 최대 전류를 25A로 제한**. 구속이 2초 이상 지속되면 정지하고 Pi에 알림 |
| **출발 시 돌입 전류**  | 정지 상태에서 갑자기 출발하면 전류가 급증                                                                  | RoboClaw와 Nav2 양쪽에**가속 제한** 설정 (예: 0.5 m/s²)                                        |
| **제자리 회전**        | 스키드 스티어는 회전할 때 바퀴가 미끄러지며 직진보다 전류가 크게 증가                                      | 웨이포인트 스캔 시**회전 속도를 낮게** 설정 (예: 0.3 rad/s)                                     |
| **배터리 전압 강하**   | 모터 피크 시 배터리 전압이 순간적으로 2~3V 떨어지고, 잔량이 적을 때는 20V 근처까지 내려감                  | DC-DC 입력 범위를**9~36V**로 넓게 잡고, 입력단에 전해 커패시터(예: 1000µF 50V)를 추가          |
| **Pi 5 전압 부족**     | 전압이 4.8V 아래로 떨어지면 Pi가 저전압 경고를 내고 성능을 낮추거나 재부팅됨                               | DC-DC 출력을**5.1V**로 설정, Pi까지의 5V 전선을 짧고 굵게(18AWG 이상) 연결                      |
| **Pi 5 USB 전류 제한** | 5V 5A 공식 어댑터가 아니면 Pi 5는 USB 전체 출력을 0.6A로 제한함 → LiDAR 기동 피크(약 1A)에서 끊길 수 있음 | `/boot/firmware/config.txt`에 `usb_max_current_enable=1` 추가 (전원이 5A를 낼 수 있을 때만)       |
| **Pi 전원 입력 위치**  | GPIO 5V 핀으로 전원을 넣으면 보호 회로를 거치지 않음                                                       | **USB-C 단자로 전원 입력** (DC-DC 출력에 USB-C 케이블 연결)                                     |
| **모터 노이즈**        | 모터 전류가 바뀔 때 생기는 전기 노이즈가 Pi·LiDAR에 영향                                                  | 모터 전원선과 신호선을 분리 배선. 접지는 배터리 마이너스 한 점에서 모음(스타 접지)                    |
| **E-Stop 접점 용량**   | 직류 대전류는 끊을 때 아크가 커서 일반 스위치 접점이 녹을 수 있음                                          | E-Stop 버튼은**컨택터 코일만 차단**하고, 실제 모터 전류는 DC 100A급 컨택터가 끊음               |

### 7. 전력 예산과 배터리 검토

| 구분                                    | 평균 소비전력                          |
| --------------------------------------- | -------------------------------------- |
| 5V 레일 (Pi 5, AI HAT+, 카메라, LiDAR)  | 13W                                    |
| DC-DC 변환 손실 (약 10%)                | 1.5W                                   |
| 컨택터 코일                             | 5W                                     |
| **전장부 소계**                   | **약 20W**                       |
| 모터 ×4 (순찰·정지 반복, 평균) (가정) | 100W                                   |
| **합계**                          | **약 120W (25.6V 기준 약 4.7A)** |

- 4시간 운용에 필요한 에너지: 120W × 4h ≈ **480Wh**
- 배터리 용량: 25.6V × 30Ah ≈ **770Wh** → 이론상 약 6.4시간
- **피크 방전 검토**: 최대 51A ÷ 30Ah ≈ **1.7C** → LiFePO4가 감당할 수 있는 범위
- **BMS 조건**: 연속 방전 **30A 이상**, 순간 방전 **60A 이상**(수 초). 피크 전류가 BMS 순간 한계를 넘으면 BMS가 전원을 끊어 로봇이 멈춘다.
